# Hotel Booking

FastAPI + SQLAlchemy + SQLite + Jinja2. Сеть из 3 отелей и 197 номеров (демо-данные), система ролей.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Откройте http://127.0.0.1:8000

> Схема БД изменилась. **Удалите старый `hotel.db`** перед запуском — база создастся заново.

## Первый вход (суперадмин)

При первом запуске создаётся суперадмин. По умолчанию: `admin@hotel.local` / `admin12345`.
**Смените это** — задайте свои значения до первого запуска:

```bash
export SUPERADMIN_EMAIL="you@example.com"
export SUPERADMIN_PASSWORD="длинный-пароль"
export SECRET_KEY="длинная-случайная-строка"
```

Остальных сотрудников создаёт суперадмин (`/admin/staff`) или менеджер с выданным правом (`/manager/staff`).
Публичная регистрация всегда создаёт только **клиента**.

## Роли и права

| Роль | Что может |
|---|---|
| **Гость** (не вошёл) | Каталог отелей, номера, отзывы, сравнение цен (`/hotels`), регистрация. Бронировать нельзя |
| **Клиент** | Поиск и бронь, оплата (демо), отмена, история поездок, отзывы после выезда, обращения в поддержку, профиль и смена пароля. Только свои брони |
| **Ресепшен** `/reception` | Все брони (гость, отель/номер, даты, срок до выезда), заселение/выселение, статус уборки номеров |
| **Менеджер** `/manager` | Модерация новых отелей, споры, ручной возврат средств, блокировка пользователей-нарушителей, временная блокировка номеров |
| **Суперадмин** `/admin` | Всё вышеперечисленное + финансы и комиссия, создание/удаление менеджеров и ресепшена, управление правами менеджеров |

Права менеджера, которые настраивает суперадмин (`/admin/staff`):
- «создавать ресепшен» (по умолчанию выключено);
- «добавлять отели и номера» (по умолчанию включено; можно ограничить).

## Бизнес-правила

- Статусы брони: ожидает оплаты → оплачена → проживает → выселен; либо отменена.
  Номер занят в статусах «ожидает оплаты», «оплачена», «проживает».
- Отмена брони клиентом возможна до заезда. Если бронь была оплачена, возврат оформляет менеджер (`/manager/disputes`).
- Заселить можно оплаченную бронь в период проживания и только в **чистый** номер.
  После выселения номер автоматически получает статус «Нужна уборка».
- Отель, добавленный менеджером, попадает на модерацию; одобрить его должен **другой** менеджер или суперадмин.
  Отель суперадмина публикуется сразу.
- Блокировка номера не создаётся, если на эти даты уже есть брони.
- Заблокированный пользователь не может войти, текущая сессия сбрасывается.
- Менеджер блокирует только клиентов; суперадмина заблокировать нельзя.

## Что в демо-режиме

- **Оплата — имитация.** Реального платёжного шлюза и ввода карт нет: кнопка «Оплатить (демо)» создаёт запись платежа.
  Возврат тоже «ручной» — меняет статус платежа. Шлюз подключается в `routers/customer.py` (`pay`) и `routers/manager.py` (`refund`).
- Названия отелей, адреса, телефоны, ссылки на приложение — вымышленные (`seed.py`, `CONTACTS` в `deps.py`).

## Структура

```
main.py          приложение, middleware, подключение роутеров
database.py      подключение к SQLite
models.py        User, Hotel, Room, Booking, Payment, Review, Dispute, RoomBlock, Setting
constants.py     роли и статусы
deps.py          авторизация, проверка ролей, рендер шаблонов
services.py      валидация, проверка занятости номеров
security.py      хеширование паролей (PBKDF2)
seed.py          демо-данные, первый суперадмин
routers/         public, auth, customer, reception, manager, admin
templates/       Jinja2-шаблоны
static/          CSS
```
